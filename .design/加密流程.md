各密钥职责

|密钥|类型|作用|存储位置|
|--|--|--|--|
|主密码|用户输入|派生 K_master|不存储|
|K_master|AES-256|验证主密码；加密/解密本机 RSA 私钥|仅内存，用完丢弃|
|设备私钥|RSA-3072|解密 Data Key；签名设备身份|本地，用 K_master 加密存 DB|
|设备公钥|RSA-3072|供其他设备加密 Data Key 给它|服务器（明文）|
|Data Key|AES-256|加密所有密码记录和备注|服务器（用各设备公钥加密后）|
|密码记录密钥|实际就是 Data Key|同 Data Key|不单独存在|

# 1. 密钥架构总览
```text
主密码（用户记忆，所有设备相同）
        │ PBKDF2 + salt
        ▼
   K_master（AES-256）       ← 存入 Android Keystore（不直接用于加解密数据）
        │
        ├── 用于验证主密码正确性（Magic Text）
        └── 用于加密设备私钥（每个设备有自己的 RSA 密钥对）
                │
                ▼
         设备私钥 (RSA-3072)    ← 解密 Data Key
                │
                ▼
           Data Key (AES-256)  ← 真正加密所有密码记录
```
K_master：从主密码派生，不用于直接加密密码记录，只负责验证主密码和解锁本机设备私钥。

设备密钥对 (RSA-3072)：每台设备唯一。私钥用 K_master 加密后存本地；公钥存服务器，供其他设备加密 Data Key 给它。

Data Key (AES-256)：完全随机生成，所有设备共用，加密所有密码记录。Data Key 本身用各设备的公钥加密后存放在服务器或通过物理介质交换。

# 2. 数据库表结构
## 2.1 设备信息表 devices
```kotlin
@Entity(tableName = "devices")
data class DeviceEntity(
    @PrimaryKey val deviceId: String,       // UUID，本地生成，全局唯一
    val deviceName: String,                 // 设备名称，如 "Pixel 7"
    val publicKey: String,                  // 该设备的 RSA 公钥 (Base64)
    val encryptedDataKey: String?,          // 用本机公钥加密的 Data Key 密文（方便离线）
    val isCurrentDevice: Boolean = false,   // 是否为本机
    val createdAt: Long
)
```
## 2.2 主密码相关 key_pair（简化，只保留必要字段）
```kotlin
@Entity(tableName = "key_pair")
data class KeyPairEntity(
    @PrimaryKey val id: Int = 1,
    val salt: String,                   // PBKDF2 盐
    val magicTextIv: String,
    val magicTextCipher: String,        // "PWD_MASTER_VERIFY_OK" 密文
    val encryptedPrivateKey: String,    // 用 K_master 加密的设备私钥
    val privateKeyIv: String,
    val passwordHint: String?
)
```
## 2.3 密码记录表 passwords（统一格式，去除冗余 IV）
```kotlin
@Entity(tableName = "passwords")
data class PasswordEntry(
    @PrimaryKey val id: String,         // UUID，创建设备生成，全局唯一
    val title: String,
    val username: String,
    val encryptedPassword: String,      // base64(iv):base64(ct)，用 Data Key 加密
    val encryptedNotes: String?,        // 同上，null 表示无备注
    val url: String?,
    val tags: String?,                  // 标签，用逗号分隔或关联表（按需）
    val createdDeviceId: String,        // 创建该记录的设备 ID
    val lastModifiedDeviceId: String,   // 最后修改该记录的设备 ID
    val createdAt: Long,
    val updatedAt: Long,
    val syncVersion: Int = 1,           // 乐观锁版本号（服务器同步用）
    val isDeleted: Boolean = false      // 软删除
)
```
# 3. 初始化流程（首次设置主密码）
用户输入主密码 → 生成随机 salt（32 字节），用 PBKDF2 派生 K_master。

在 Android Keystore 中生成一个 AES-256 密钥（受硬件保护，可选要求用户生物识别），将 K_master 导入 Keystore 或通过 Keystore 加密 K_master 后存储密文。更安全的做法是：直接用 Keystore 生成一个“主保护密钥”，用 K_master 授权解锁，但为简化，我们先说“K_master 存入 Keystore”实际上是指 Keystore 生成一个密钥对，用 K_master 加密私钥 或 Keystore 存储一个只能由生物识别/设备锁屏解锁的密钥，再用该密钥加密 K_master。为满足你的设计“K_master 存入 Android Keystore”，我们折衷：

利用 Android Keystore 生成一个 AES 密钥 KeystoreKey，设定 setUserAuthenticationRequired(false) 方便后台访问。

用 KeystoreKey 加密 K_master，密文存 SharedPreferences（或 key_pair 表新增字段）。

实际使用时，通过 Keystore 解密得到 K_master，用完即从内存销毁。这样 K_master 明文永不长期驻留，且受硬件保护。

生成 RSA-3072 设备密钥对，将公钥 Base64 编码，私钥用 K_master (AES-GCM) 加密，存入 key_pair.encryptedPrivateKey。

加密 Magic Text，存入 key_pair 用于后续验证。

生成随机的 Data Key (AES-256, 32 字节)。

用本地公钥加密 Data Key，得到 encryptedDataKey_self，存入本机 devices 表（方便离线取用）。

将本机设备信息（deviceId, deviceName, publicKey）写入本地 devices 表，标记 isCurrentDevice = true。

服务器同步：上传本机设备信息（deviceId, publicKey）和用本机公钥加密的 Data Key 到服务器（关联 deviceId）。服务器存储 {deviceId, publicKey, encryptedDataKey}。

物理备份导出（可选）：引导用户导出“恢复包”，包含 salt、本机公钥、encryptedPrivateKey、encryptedDataKey_self、设备信息等，用主密码再次加密导出文件（或生成恢复二维码）。

# 4. 添加新设备流程
假设设备 A 已存在，要在设备 B 上用同一个主密码加入同步。

## 4.1 通过服务器同步（在线授权）
设备 B 输入主密码 → 派生 K_master_B，生成自己的设备密钥对。

设备 B 上传自己的 deviceId、publicKey_B 到服务器，并标记“请求授权”。

设备 A（已在线）收到授权请求，用户确认后，设备 A 从服务器获取设备 B 的公钥。

设备 A 用 Data Key 解密自己的 encryptedDataKey_self，然后用设备 B 的公钥加密 Data Key，得到 encryptedDataKey_B，上传服务器关联设备 B。

设备 B 从服务器拉取自己的 encryptedDataKey_B，用私钥解密得到 Data Key，存入本地 devices 表。

设备 B 开始拉取所有密码记录（它们都用 Data Key 加密），用 Data Key 解密后存入本地数据库。

后续设备 B 也能正常读写，同步版本号解决冲突。

## 4.2 通过物理介质（离线恢复/导出导入）
设备 A 导出“同步包”（加密文件或二维码），包含：

salt

encryptedPrivateKey (设备 A 的，可选，若用户希望在 B 上导入 A 的身份？不，我们目标是每个设备有自己的身份，所以导出的是 Data Key 而不是 A 的私钥)

encryptedDataKey_A (用设备 A 公钥加密的，但 B 没有 A 的私钥无法解，所以错误)

正确的物理备份设计：

导出的是用 K_master 加密的 Data Key，因为主密码在 B 上也一样，可以直接解密。即：导出文件包含 salt、encryptedDataKey_withKmaster（用 K_master 加密的 Data Key）、所有密码记录的密文。

设备 B 输入相同主密码，派生 K_master，解密得到 Data Key，然后解密密码记录并导入。但这样 B 就没有自己的设备密钥对，不利于未来服务器同步。可让 B 在导入后自动生成本机密钥对，然后重新用服务器同步（如果启用了服务器同步）。

兼顾物理介质与服务器同步的设计：

物理导出/导入只作为手动恢复整个数据库的手段，包含完整的加密密码记录和加密 Data Key（用 K_master 加密），不含任何设备私钥。导入后，目标设备必须用主密码解锁，然后该设备会成为一个新的“设备”，生成自己的密钥对，并将自己的公钥和加密 Data Key（用自己公钥加密）上传服务器。这样既保持了物理备份的可行性，又不破坏设备身份唯一性。

# 5. 解锁流程（日常使用）
应用启动 → 检查 key_pair 存在性。

从 Android Keystore 解密获取 K_master（需生物识别或设备锁屏验证，如果设置）。

用 K_master 解密本地私钥 encryptedPrivateKey，再用私钥解密本地存储的 encryptedDataKey（来自 devices 表）得到 Data Key。

Data Key 存入 CryptoSession，用于后续加解密。

立即从内存中清除 K_master 和私钥（可保留私钥到内存直到锁定）。

如果需要离线，直接使用本地 Data Key；在线时，可定期检查 Data Key 是否被轮换（未来扩展）。

# 6. 同步冲突解决
每条记录有 syncVersion 和 updatedAt。

服务器端保存每个 record 的最新版本号。

上传时：客户端发送 currentVersion，服务器检查是否等于最新，若相等则更新并递增版本；否则返回冲突数据，由用户决定合并（保留远程、保留本地或手动合并）。

删除采用软删除 isDeleted = true，同步时以最大版本为准，冲突时保留删除操作通常优于修改操作（取决于业务规则）。

# 7. “不能备份”的实现
你的要求：可以使用服务器同步，但不能备份。我理解为：

服务器只提供实时同步功能（增量更新），不提供“一键备份整个库到云端，恢复时下载一个完整文件”的服务。

数据只能在设备间流转，服务器不保留历史版本快照，不提供回滚。

物理介质导出备份功能在本地完成，不受此限制。

技术上，只需服务器不提供全量导出接口，不保留多版本记录（仅保留最新版本），并明确声明无备份服务即可。

# 8. 安全性分析
环节	安全保障
K_master 保护	Android Keystore 硬件加密，用完即焚
设备私钥	用 K_master 加密存储，主密码泄露+数据库泄露方可解开
Data Key	随机生成，用各设备公钥加密传输，服务器无明文
密码记录	AES-256-GCM 加密，密钥永远不出 TEE（若用 Keystore 间接保护）
服务器攻破	仅有公钥和加密 Data Key，无法解密任何密码数据
物理备份泄露	备份文件用 K_master 加密 Data Key 部分，需要主密码才能解开，等同主密码安全性
添加新设备	必须由已授权设备确认并用目标公钥加密 Data Key，防止未授权设备加入
# 9. 代码结构建议
CryptoManager：保留底层 AES、RSA、PBKDF2 操作。

KeystoreHelper：封装 Android Keystore 中生成/存取 K_master 的逻辑。

SessionManager（原 CryptoSession）：持有 Data Key，提供 unlock(masterPassword) 方法完成：

派生 K_master（via CryptoManager）
解密私钥（via CryptoManager）
解密 Data Key（via CryptoManager）
SyncManager：处理与服务器的通信（设备注册、拉取加密 Data Key、上传/下载密码记录）。

BackupHelper：实现物理介质导入/导出，生成用 K_master 加密的备份包。
