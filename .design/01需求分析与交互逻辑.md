# 需求与交互逻辑

命令行结构、核心工作流、同步触发、多设备协作四个方面来设计交互模式。

## 1 命令体系（子命令风格，类似 git / cargo）

假设工具名叫 vlt，顶层命令大致如下：

```bash
vlt init                  # 初始化当前设备，生成密钥对，设置主密码
vlt unlock                # 输入主密码，开启会话（可选）
vlt lock                  # 手动锁定会话，清除内存中的密钥
vlt add                   # 交互式添加一条密码
vlt list [--tag <tag>]    # 列出所有条目（可筛选标签）
vlt show <id|title>       # 显示指定条目的详细信息（默认隐藏密码，--reveal 显示）
vlt edit <id|title>       # 编辑条目（交互或传参）
vlt rm <id|title>         # 删除条目（软删除）
vlt tag <id> <tag...>     # 给条目打标签 / 移除标签
vlt sync [push|pull]      # 手动同步：推送到服务器 / 从服务器拉取
vlt dev list              # 列出已知设备及其状态
vlt dev authorize <id>    # 授权新设备（为其补充历史密钥包）
vlt config                # 查看 / 修改配置（服务器地址、自动同步策略等）
```

设计原则：

所有需要访问明文数据的命令（add / list / show 等）都依赖一个未过期的主密码缓存（内存中保留派生的密钥，一定时间后自动过期）。

如果会话已过期，执行任何敏感命令前会弹出交互式密码输入（或者支持 --password 参数，但不建议）。

## 2 初始化流程（新设备首次使用）

```bash
$ vault init
Enter a master password: ********
Confirm: ********
Device name (optional): MacBook Pro
Generating RSA key pair...
Registering device with server...
Done. Your device ID is: d4f8...
```

背后发生了什么：

用 Argon2id 从主密码派生一个强密钥，只用来加密本地的 RSA 私钥（私钥加密后存到本地 SQLite 的 devices 表）。

生成 RSA 3072 密钥对，公钥上传到服务器 devices 表。

私钥明文永不落盘，只在内存中保留（会话期间）。

客户端将服务器地址和认证令牌写入本地配置文件（令牌可手动复制或生成）。

关键点： 主密码 ≠ 数据加密密钥，主密码只保护本地私钥。真实的数据密钥（DEK）是随机的，用 RSA 分发。这样主密码可以更改而不需要重新加密所有条目（只需重新加密本地私钥即可）。

## 3 日常使用（增删改查）

添加条目（交互式）：

```bash
$ vault add
Title: GitHub
Username: alice@example.com
Password (generate? y/n): y
Generated password: xK9$2lPq... (copy to clipboard)
URL (optional): https://github.com
Notes (optional): work account
Tags (comma separated): dev, work
Entry added. ID: 7c9f...
```

列表与搜索：

```bash
$ vault list
ID       Title         Tags
7c9f...  GitHub        dev, work
a3b2...  Email         personal
...

$ vault list --tag work
7c9f...  GitHub        dev, work
```

查看详情：

```bash
$ vault show github    # 支持标题模糊匹配
Title: GitHub
Username: alice@example.com
Password: [hidden]       # 用 vault show github --reveal 显示并复制
URL: https://github.com
Tags: dev, work
Notes: work account
```

编辑与删除：

```bash
$ vault edit github      # 进入交互编辑，可修改任意字段、添加/移除标签
done
$ vault rm github        # 软删除，同步后服务端也标记 is_deleted=true
done
```

标签管理：

```bash
$ vault tag github +personal -work   # 增加 personal，移除 work
done
```

所有写操作（add/edit/rm/tag）完成后，自动触发一次 sync push（如果配置了自动同步），或者提示用户手动推送。

## 4 同步机制（对用户透明）

手动同步（默认推荐，让用户掌控）

```bash
$ vault sync push    # 将本地有变更的条目推送到服务器
done
$ vault sync pull    # 从服务器拉取其他设备的更新
done
```

自动同步（可选配置）
配置 auto_sync = true 后，任何写操作后自动执行 push，任何读操作前自动执行 pull（或每 N 分钟后台同步）。

考虑到是自用，冲突概率低，采用最后写入胜出（LWW）策略，updated_at 为准。

拉取时只获取 updated_at > 上次同步时间 的条目，增量同步，节省流量。

用户在同步时无需关心加密细节，工具内部完成：

推：取本地 sync_status != synced 的条目，用已知设备公钥分别加密 DEK，上传 entries + entry_keys。

拉：从服务器获取新条目和属于本设备的 encrypted_dek，用本地私钥解密 DEK，再解密内容写入本地。

## 5 新设备加入与授权（核心体验）

这是多设备场景最关键的一步，需要简单且安全。

场景： 你有一台 MacBook 已经存了 50 个密码，现在新买了一台 Linux 桌面，想在上面同步所有数据。

步骤 1：在新设备上初始化

```bash
$ vault init
Enter master password: ******   (必须与旧设备相同)
Device name: Linux Desktop
Device registered. ID: a1b2...
此时新设备已生成自己的 RSA 密钥对，公钥已上传服务器，但还无法解密任何历史条目，因为服务器上那些条目的 entry_keys 没有用新设备公钥加密的版本。
```

步骤 2：在旧设备上授权新设备

```bash
$ vault device list          # 显示已知设备
ID       Name               Last Seen
d4f8...  MacBook Pro        (this device)
a1b2...  Linux Desktop      never

$ vault device authorize a1b2
Found 50 existing entries. Re-encrypting DEKs for device 'Linux Desktop'...
Uploading new key packages...
Done. New device can now access all entries.
```

自动授权选项： 你也可以设计为“自动授权”模式，即任何新设备出现在服务器上，本地在下次同步时自动为其生成缺失的 entry_keys。但对于密码管理器，显式授权更安全，让用户知道有新设备加入。

完成授权后，回到新设备上执行 vault sync pull，所有密码即可解密使用。

## 6 主密码处理与安全会话

主密码在内存中保留的派生密钥有有效期（例如 15 分钟），过期后需要重新输入。

复制到剪贴板的密码应在几秒后自动清除（可选）。

支持环境变量 VAULT_PASSWORD 或 --password-file 方便脚本使用（自用可以考虑）。

本地数据（SQLite）可以进一步用操作系统的密钥链加密，但不是必须。
